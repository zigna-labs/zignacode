> **ベータ版です。** 現在は Windows のみの初期ベータです。リリースの間で、機能が変わったり壊れたりすることがあります。

zignacode は、司令塔のエージェント（Claude Code、Codex、OpenCode など）1 つを、チームに変えます。作業を計画書に書くと、zignacode がサブエージェントを並列に出動させ、それぞれを切り離した git ワークツリーで動かし、結果を検証してから元のブランチへマージします。

- **むやみに並列にしない** — 並列にすること自体を目的にしません。どれだけ積極的に分けるか、誰がコードを書くかをあなたが選べます。小さな変更は司令塔がそのまま行い、分けても速くならない計画は、始める前に知らせます。詳しくは「[必要なときだけ並列に](#必要なときだけ並列に)」へ。
- **本当の並列、衝突ゼロ** — サブエージェントごとに専用のワークツリーとブランチを用意します。ファイルの書き込みの衝突も、ビルドのロックも、作業中のフォルダに中途半端な変更が残ることもありません。
- **計画 → 出動 → 検証 → マージ** — タスクは依存関係のグラフとして動きます。`[verify: …]` を付けたステップは、そのコマンドが通ったときだけマージされます。レビューのステップは、依存先がマージされてから始まります。
- **動きが見えるダッシュボード** — DAG の表示とエージェントごとのカードで、作業中・待機中・停止中・完了がひと目でわかり、差分もワンクリックで見られます。
- **あなたのツールの設定に手を加えない** — フック、MCP サーバー、設定を、ツールのグローバル設定（`~/.claude.json`・`~/.codex/` など）に書き込みません。連携は、zignacode の中で起動したエージェントにだけ付けます。
- **閉じても消えないターミナル** — ウィンドウを閉じても、ターミナル（とその中で動くエージェント）は動き続けます。開き直せば、元の画面に戻ります。
- **いつものエージェントをそのまま** — 普段使っているエージェントの CLI を、それぞれのログインのまま使います。
- **小さい** — インストーラー 1 つ（ダウンロード約 42 MB、インストール後 約 120 MB）。Node.js も Bun も不要です。

## 必要なときだけ並列に

エージェントを増やせば早く終わる、とは限りません。サブエージェントを 1 つ増やすたびに、起動の時間・トークン・マージの手間がかかります。そこで zignacode では、どこまで任せるかをあなたが決められ、分けても得にならないときは止まって知らせます。

**どのモードでも、ほかの作業に依存する作業や、同じファイルを触る作業は並列にしません。** 並んで動くのは、計画書の上で独立している作業だけです。

- **委譲モード** — どこまで任せるか、並列にするかを誰が決めるか
  - `off` — サブエージェントを使わず、司令塔だけで進める
  - `opportunistic`（おまかせ）— 並列にしても、エージェントを起動する手間に見合うほど早くならない計画は、zignacode が 1 つずつ順番に動かす
  - `orchestration`（計画どおり）— 計画書の上で独立したステップを、書かれたとおり並列で動かす（見合わないときも警告だけ出して並列にする）
- **タスクの大きさ** — 作業は、エージェントの数の目標に合わせて分けるのではなく、1 体が持ち時間に余裕をもって終わる大きさに分けます。タスクの数に上限はありません。同時に動かす数は `maxWorkers` で決まります。
- **誰がコードを書くか** — 数字 1 つで決まります。委譲がオンのときは、*N* 行以下（既定は 30 行。変更できます。0 にすると常に任せます）の変更は司令塔が自分で書き、それより大きい変更はサブエージェントに任せます。委譲が `off` のときは、常に司令塔が書きます。
- **自動マージ** — 設定で ON / OFF を切り替えられます。ON なら、`[verify: …]` のコマンドに合格したステップを自動でマージします。OFF なら、1 つずつ自分でマージします。
- **計画書のチェック** — 出動の前に、並列にして縮む時間を見積もります。エージェントを起動する手間を下回るときは警告します（`opportunistic` なら、1 つずつ順番に動かします）。
- **重なりの見張り** — 同じファイルを触るステップは、自動で順番待ちにします。並列のエージェントが同じファイルを奪い合うことはありません。
- **依存関係** — `[after: N]` を付けたステップは、依存先が終わるまで始めません。

## インストール

1. [最新のリリース](../../releases/latest) から `Zignacode_x.y.z_x64-setup.exe` をダウンロードします。
2. 実行します。ベータ版のインストーラーには**まだコード署名がない**ため、「Windows によって PC が保護されました」と表示されることがあります。**詳細情報 → 実行** で進めてください。
3. スタートメニューから **Zignacode** を起動します。

## 最初の 5 分

1. 左ペインの **＋** を押して、git リポジトリのフォルダを選びます（どのドライブでも選べます）。`C:\Windows`、Program Files、ProgramData、AppData、ドライブ直下、ホームフォルダは、安全のために開けないようにしています。
2. **はじめに、並列で動かすための設定をします。** ステータスバー左端の **⚙** から設定画面を開きます。
   - **委譲** — `opportunistic`（おまかせ）か `orchestration`（計画どおり）を選びます。`off` にすると、サブエージェントは動きません（既定は `opportunistic` です）。
   - **ツール** — zignacode が、PC にインストール済みでログインしているエージェントの CLI（Claude Code、Codex、OpenCode、pi、omp、Antigravity CLI）を検知し、それぞれで使えるモデルの一覧を出します。
   - **役割** — サブエージェントは 5 つの役割で働きます。役割ごとに、使うツールとモデルを割り当てます。
     - `coder` — 本実装・UI 開発・リファクタリング
     - `researcher` — コードの探索・依存関係の調査・仕様の確認
     - `reviewer` — 差分の監査・バグの発見・最小限の修正提案
     - `tasker` — テストの量産・型エラーの修正・定型作業
     - `architect` — 設計方針・トレードオフの検討・深い推論
   - サブエージェントには速くて安いモデル（ツールが対応していれば、DeepSeek など）を割り当て、司令塔には強いモデルを使う、といった使い分けができます。
3. 中央のターミナルで、司令塔のエージェントを起動します（例: `claude` や `codex`）。
4. 独立した作業に分けられることを頼みます。例:
   「zignacode で計画を立てて出動して。サインアップのフォームに入力チェックを足すのと並行して、日付ユーティリティのテストを書いて。両方終わったらレビューして。」
5. 右側のダッシュボードを見てください。サブエージェントが、それぞれのワークツリーで並んで動き始めます。検証に通ったステップは自動でマージされ（自動マージは既定で ON です）、そのあとでレビューが走ります。
6. カードを開けば差分を読めます。カードの **merge** から、自分でマージすることもできます。
